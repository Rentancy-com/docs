---
title: "POST /v2.0/calendar — Create a Calendar Event"
description: "Create a task or appointment on a Lofty lead's calendar using POST /v2.0/calendar. Set the type field to TASK or APPOINTMENT to control what is created."
---

Creates a task or appointment for the target lead. The `type` field determines which kind of entry is created. For tasks, the `taskWay` field specifies the communication channel. For appointments, supply an `address` for the meeting location.

The caller must have manage permission on the lead; otherwise the request returns `400 PERMISSION_DENIED`.

<Note>
  This endpoint uses a composite ID format in its response. The returned `id` (e.g., `88001-task` or `88002-appointment`) is required for update and delete operations via `PUT /v2.0/calendar/{calendarId}` and `DELETE /v2.0/calendar/{calendarId}`.
</Note>

## Request body

<ParamField body="type" type="string" required>
  Calendar entry type. Accepted values: `TASK`, `APPOINTMENT`. Case-insensitive.
</ParamField>

<ParamField body="content" type="string" required>
  Description or title of the event.
</ParamField>

<ParamField body="leadId" type="integer" required>
  ID of the lead this event is associated with.
</ParamField>

<ParamField body="timeZoneCode" type="string" required>
  IANA timezone code for the event, e.g., `America/Chicago`.
</ParamField>

<ParamField body="startAt" type="string">
  Start time in ISO 8601 format with timezone, e.g., `2026-05-12T14:00:00GMT`. Takes precedence over `startAtMs` when both are provided.
</ParamField>

<ParamField body="endAt" type="string">
  End time in ISO 8601 format. Takes precedence over `endAtMs` when both are provided.
</ParamField>

<ParamField body="startAtMs" type="integer">
  Start time as a Unix timestamp in milliseconds. Used when `startAt` is not provided.
</ParamField>

<ParamField body="endAtMs" type="integer">
  End time as a Unix timestamp in milliseconds. Used when `endAt` is not provided.
</ParamField>

<ParamField body="taskWay" type="string">
  Communication channel for `TASK` type entries. Accepted values: `Call`, `Email`, `Text`, `Other`.
</ParamField>

<ParamField body="assignedRole" type="string">
  Role assignment for `TASK` type entries. Accepted values: `Agent`, `Assistant`.
</ParamField>

<ParamField body="address" type="string">
  Meeting location for `APPOINTMENT` type entries.
</ParamField>

## Example requests

### Create a task

```bash
curl -X POST https://api.lofty.com/v2.0/calendar \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "TASK",
    "content": "Send listing agreement for review",
    "leadId": 563172647619608,
    "taskWay": "Email",
    "assignedRole": "Agent",
    "startAt": "2026-05-10T09:00:00GMT",
    "endAt": "2026-05-10T09:30:00GMT",
    "timeZoneCode": "America/Los_Angeles"
  }'
```

### Create an appointment

```bash
curl -X POST https://api.lofty.com/v2.0/calendar \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "APPOINTMENT",
    "content": "Property showing — 123 Maple St",
    "leadId": 563172647619608,
    "address": "123 Maple St, Austin, TX 78701",
    "startAt": "2026-05-12T14:00:00GMT",
    "endAt": "2026-05-12T15:00:00GMT",
    "timeZoneCode": "America/Chicago"
  }'
```

## Response

```json
{
  "data": {
    "id": "88002-appointment",
    "type": "APPOINTMENT",
    "message": "success"
  }
}
```

<Tip>
  Store the returned `id` (e.g., `88002-appointment`) to update or delete this entry via `PUT /v2.0/calendar/{calendarId}` or `DELETE /v2.0/calendar/{calendarId}`.
</Tip>
