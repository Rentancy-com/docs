---
title: "DELETE /v1.0/leads/{leadId} — Delete a Lead"
description: "Move a Lofty lead to the trash with a required reason string recorded for audit purposes. The operation is reversible via the UI but not via the API."
---

Moves a lead to the trash. A `reason` query parameter is required and is stored with the record for audit purposes. The response body is empty on success.

<Warning>
  Trashing a lead removes it from all active views and workflows immediately. While the lead can be restored through the Lofty UI, there is no API endpoint to restore a trashed lead. Use this operation with care.
</Warning>

## Path parameters

<ParamField path="leadId" type="integer" required>
  The ID of the lead to trash (64-bit integer).
</ParamField>

## Query parameters

<ParamField query="reason" type="string" required>
  A free-text explanation for why the lead is being trashed. This value is stored in the lead's audit history.
</ParamField>

## Example request

```bash
curl -X DELETE "https://api.lofty.com/v1.0/leads/563172647619608?reason=Duplicate+record" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json"
```

## Response

Returns HTTP `200 OK` with an empty response body on success.

```json

```

If the lead does not exist or the caller lacks permission, the API returns `404 LEAD_NOT_EXIST`.
