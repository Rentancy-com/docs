---
title: "GET /v2.0/tasks/{taskId} — Get a Task or Appointment"
description: "Fetch a single task or appointment by ID using GET /v2.0/tasks/{taskId}. Returns lead context, agent assignment, due date, timing, type, and completion status."
---

Returns a single task or appointment by its ID. Tasks and appointments share the same `taskId` namespace — the endpoint resolves the type automatically. The caller must have manage permission on the lead that owns the task.

<Note>
  The legacy `GET /v1.0/tasks/{taskId}` returns the task alongside the lead's pipeline context. Prefer V2 for all new integrations.
</Note>

## Path parameters

<ParamField path="taskId" type="integer" required>
  ID of the task or appointment to retrieve.
</ParamField>

## Example request

```bash
curl https://api.lofty.com/v2.0/tasks/88001 \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json"
```

### Response fields

| Field | Type | Description |
|---|---|---|
| `id` | integer | Task ID |
| `leadId` | integer | ID of the associated lead |
| `leadName` | string | Full name of the associated lead |
| `content` | string | Task description |
| `type` | string | Task type: `Call`, `Email`, `Text`, `Other`, or `Appointment` |
| `assignedRole` | string | Role assigned: `Agent` or `Assistant` |
| `assignedUserId` | integer | User ID of the assigned agent |
| `startAt` | string | Start time in ISO 8601 format |
| `endAt` | string | End or due time in ISO 8601 format |
| `timeZoneCode` | string | IANA timezone code |
| `allDay` | boolean | Whether this is an all-day event |
| `finishFlag` | boolean | `true` if the task is marked complete |
| `overdueFlag` | boolean | `true` if the task is past due and not finished |
| `finishTime` | string | Timestamp when the task was completed, or `null` |
| `address` | string | Location for appointment type entries |
