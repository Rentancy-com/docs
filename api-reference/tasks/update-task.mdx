---
title: "PUT /v2.0/tasks/{taskId} — Update a Task or Appointment"
description: "Partially update an existing Lofty task or appointment. Only fields included in the request body are changed; omitted fields keep their current values."
---

Partially updates a task or appointment. Only non-null fields included in the request body are applied — omitted fields are left unchanged. At least one of `content`, `startAt`, `endAt`, or `address` must be supplied; an entirely empty request body returns `400 MISSING_PARAMETER`.

<Note>
  To mark a task as complete or revert it to incomplete, use the dedicated finish and unfinish endpoints instead of this one. See [Completing tasks](#completing-tasks) below.
</Note>

<Note>
  The legacy `PUT /v1.0/tasks/{taskId}` supports a `finishFlag` field for completion. Prefer the V2 finish/unfinish endpoints for all new integrations.
</Note>

## Path parameters

<ParamField path="taskId" type="integer" required>
  ID of the task or appointment to update.
</ParamField>

## Request body

<ParamField body="content" type="string">
  Updated description or title of the task.
</ParamField>

<ParamField body="startAt" type="string">
  Updated start time. ISO 8601 format with timezone, e.g., `2026-05-10T10:00:00GMT`.
</ParamField>

<ParamField body="endAt" type="string">
  Updated end or due time. ISO 8601 format with timezone, e.g., `2026-05-10T11:00:00GMT`.
</ParamField>

<ParamField body="timeZoneCode" type="string">
  IANA timezone code for interpreting `startAt` and `endAt`, e.g., `America/Chicago`.
</ParamField>

<ParamField body="address" type="string">
  Updated location for `Appointment` type entries.
</ParamField>

## Example request

```bash
curl -X PUT https://api.lofty.com/v2.0/tasks/88001 \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "content": "Follow up on pre-approval — rescheduled",
    "startAt": "2026-05-12T14:00:00GMT",
    "endAt": "2026-05-12T14:30:00GMT",
    "timeZoneCode": "America/Los_Angeles"
  }'
```

## Response

```json
{
  "message": "success"
}
```

## Completing tasks

To mark a task or appointment as complete without updating other fields, use the finish endpoint:

```bash
curl -X POST https://api.lofty.com/v2.0/tasks/88001/finish \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json"
```

To revert a completed task back to incomplete:

```bash
curl -X POST https://api.lofty.com/v2.0/tasks/88001/unfinish \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json"
```

<Note>
  Smart-plan tasks cannot be finished through the finish endpoint and return `TASK_IS_SMARTPLAN`. Smart-plan task completion is managed by Lofty's AI plan system.
</Note>
