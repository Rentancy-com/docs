---
title: "API Keys"
description: "Authenticate with the Lofty API using a static API key."
---

API keys provide a simple authentication method for internal tools and development. Unlike OAuth 2.0, API keys do not expire automatically and have no built-in scope control.

<Warning>
  API keys are intended for internal use only. For production integrations or any third-party access, use [OAuth 2.0](/authentication/oauth2).
</Warning>

## Obtain your API key

Navigate to **Settings → Integrations → API** in your Lofty account to view or generate your key.

Each key is bound to the account that generated it. Requests authenticated with that key inherit the account's permissions.

## Authenticate requests

Pass your API key in the `Authorization` header with the `token` prefix:

```bash
curl https://api.lofty.com/v1.0/leads \
  -H "Content-Type: application/json" \
  -H "Authorization: token <API_KEY>"
```

## Security considerations

- **Do not** expose keys in client-side code, public repositories, or logs.
- **Do not** share keys with external vendors or third parties.
- Keys are not subject to Lofty's security review process — you are responsible for access control.
- If a key is compromised, revoke it immediately in your account settings and generate a new one.

## When to use API keys

| Scenario | Recommended method |
|---|---|
| Internal automation or scripts | API Key |
| Quick prototyping and testing | API Key |
| Third-party integrations | OAuth 2.0 |
| User-facing applications | OAuth 2.0 |
| Multi-tenant platforms | OAuth 2.0 |

<Tip>
  If your use case grows beyond internal tooling, migrate to [OAuth 2.0](/authentication/oauth2) before expanding access.
</Tip>
