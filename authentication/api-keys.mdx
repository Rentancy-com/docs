Lofty supports API key authentication as an alternative to OAuth 2.0. API keys are simpler to set up — no OAuth flow required — but they come with significant security trade-offs. Use API keys only for internal tools or exploratory development where you control the environment, and where the key will never be shared with or visible to external parties.

## Find your API key

Your API key is available in your Lofty account. Navigate to **Settings > Integrations > API** to view or generate your key.

<Note>
  Each API key is tied to the user account where it was generated. Requests authenticated with that key act with that user's account permissions.
</Note>

## Make an authenticated request

Include your API key in the `Authorization` header of every request.

| Header | Value |
|---|---|
| `Content-type` | `application/json` |
| `Authorization` | `token [API_KEY]` |

<CodeGroup>

```bash cURL
curl --request GET \
  --url https://api.lofty.com/v1.0/leads \
  --header 'Content-type: application/json' \
  --header 'Authorization: token YOUR_API_KEY'
```

</CodeGroup>

Replace `YOUR_API_KEY` with the key from your Lofty account settings.

## Security requirements

<Warning>
  API keys must remain internal. Do not share them with external vendors, embed them in client-side code, or commit them to public repositories. You assume full responsibility for managing the key's usage and security.
</Warning>

Unlike OAuth 2.0 tokens, API keys are not subject to Lofty's security assessment process and do not expire automatically. If a key is compromised, you must revoke and replace it manually. There is no built-in scope control — the key provides access consistent with the account it belongs to.

## Limitations compared to OAuth 2.0

| | API key | OAuth 2.0 |
|---|---|---|
| **Expiration** | No automatic expiration | Access tokens expire automatically |
| **Security assessments** | Not subject to review | Subject to Lofty's security review |
| **Scope control** | No built-in restrictions | Scoped to specific API endpoints |
| **Responsibility** | Client manages all security | Shared between client and Lofty |
| **External sharing** | Never — internal use only | Supported through authorized OAuth flows |

## When to use API keys

API keys are appropriate when:

- You're building an **internal tool** used only within your own organization
- You need to **test the API quickly** before committing to a full OAuth integration
- You have a **server-side script** running in a controlled environment with no external exposure

For anything user-facing, multi-tenant, or shared with other organizations, use OAuth 2.0.

<Tip>
  Lofty strongly recommends OAuth 2.0 whenever possible. If your use case grows beyond internal tooling, migrate to OAuth 2.0 before expanding access. See [Authenticate with OAuth 2.0](/authentication/oauth2) to get started.
</Tip>
