All API requests require authentication via the `Authorization` header. Lofty supports two methods:

| Method | Use case | Header format |
|---|---|---|
| **OAuth 2.0** | Production integrations, third-party apps | `Bearer <access_token>` |
| **API Key** | Internal tools, testing | `token <api_key>` |

## Choosing a method

<CardGroup cols={2}>
  <Card title="OAuth 2.0" icon="shield-check" href="/authentication/oauth2">

  </Card>
  <Card title="API Keys" icon="key" href="/authentication/api-keys">

## Base URL

All API endpoints use the following base URL:

```
https://api.lofty.com
```

## Request format

Include the following headers in every request:

```bash
curl https://api.lofty.com/v1.0/leads \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <access_token>"
```

## Rate limiting

API requests are subject to rate limits. If you exceed the limit, the API returns HTTP `429 Too Many Requests`. Implement exponential backoff in your retry logic.

## Common errors

| HTTP Status | Code | Description |
|---|---|---|
| `401` | — | Invalid or missing authentication credentials. |
| `403` | `200100` | Token is valid but lacks the required permission scope. Grant the scope in the [Developer Portal](https://api.lofty.com/vendor/frontend/static/index.html#/login) and re-authorize. |
| `429` | — | Rate limit exceeded. Retry with backoff. |
